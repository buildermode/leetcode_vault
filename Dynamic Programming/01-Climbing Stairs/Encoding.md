## Who, What, Where, When, Why, How
**Who**: You are a climber at the bottom of a staircase.

**What**: You need to count all the distinct ways to reach the top by taking 1 or 2 steps at a time.

**Where**: At each position on the stairs.

**When**: At each step, you have a choice: take 1 step forward or 2 steps forward.

**Why**: This is a classic dynamic programming problem because the number of ways to reach step `n` depends only on the ways to reach steps `n-1` and `n-2`.

**How**: Use a DP array where `dp[i]` = `dp[i-1] + dp[i-2]` (sum of ways from previous steps).

## Real-World Example
Imagine you're implementing a feature recommendation system. Users navigate through a wizard with multiple pages. Each page can take 1 click or 2 auto-skip actions. You need to calculate all unique paths through the wizard to understand user flow complexity. The staircase is the wizard pages, and the steps are the navigation options.

## Step-by-Step Explanation
1. **Base cases**: To reach step 1, there's 1 way. To reach step 2, there are 2 ways (1+1 or 2).
2. **Recurrence relation**: For any step `i`, you arrive from step `i-1` (taking 1 step) or step `i-2` (taking 2 steps). So the total ways = ways to reach `i-1` + ways to reach `i-2`.
3. **Fill the DP table**: Start from step 3 and fill up to step `n` using the recurrence.
4. **Return the result**: `dp[n]` contains the answer.

## Visual Description
```
Step:    1   2   3   4   5
Ways:    1   2   3   5   8

Path building:
- Step 1: Starting point. There's only 1 way to reach it: start and take 1 step.
- Step 2: You can reach it from step 0 (take 2 steps) or step 1 (take 1 step). That's 2 ways: [1,1] or [2].
- Step 3: Can come from step 2 (2 ways) or step 1 (1 way) = 2 + 1 = 3 ways: [1,1,1], [1,2], [2,1]
- Step 4: Can come from step 3 (3 ways) or step 2 (2 ways) = 3 + 2 = 5 ways: [1,1,1,1], [1,1,2], [1,2,1], [2,1,1], [2,2]
- Step 5: Can come from step 4 (5 ways) or step 3 (3 ways) = 5 + 3 = 8 ways

Notice: This is the Fibonacci sequence! Each step's count is the sum of the two previous counts.
```

## Key Insight to Remember
The Climbing Stairs problem is essentially asking: **"How many Fibonacci numbers have we generated by step n?"** The pattern grows exponentially because each position combines all possibilities from its predecessors—a classic DP pattern where subproblems overlap and solutions build incrementally.
## Why Dynamic Programming?
This problem is a textbook DP problem because it has two critical properties:

1. **Overlapping Subproblems**: To compute ways to reach step 5, we need ways to reach steps 4 and 3. To compute ways to reach step 4, we also need ways to reach step 3. Without memoization, step 3 would be recalculated exponentially many times. A naive recursive approach would have exponential time complexity because the same subproblems get solved repeatedly.

2. **Optimal Substructure**: The best (and only) way to solve the problem at step `n` depends entirely on the solutions to steps `n-1` and `n-2`. We combine these solutions directly (by summing them) without any further decision-making. This means we can build up the solution incrementally.

**Why not greedy?** A greedy approach (always take the largest step possible) would fail here. For n=5, greedy gives 2+2+1=5, but we need to count ALL paths, not just one optimal path.

## Time Complexity: O(n) - Reasoning & Value
**Why O(n)?**
- We compute `dp[i]` exactly once for each step from 1 to n
- Each computation involves a single addition: `dp[i] = dp[i-1] + dp[i-2]`
- No nested loops, no repeated work

**Value/Benefit**: This is linear time, which is optimal because we must at least read the input (n). Compared to naive recursion which is O(2^n), DP reduces an exponential problem to linear time—a massive improvement. For n=50, O(n) = 50 operations vs O(2^n) = over a quadrillion operations.

**Real-world impact**: We can now handle large staircases (n=1000+) instantly, whereas exponential solutions would timeout.

## Space Complexity: O(n) - Reasoning & Value
**Why O(n)?**
- We store a DP array of size n+1 to hold `dp[0]` through `dp[n]`
- Each value stores one integer representing the number of ways
- No additional data structures beyond this array

**Value/Benefit**: O(n) space is necessary if we want to solve the problem bottom-up and avoid function call overhead. However, this can be optimized.

**Space Optimization Possible**: Since `dp[i]` depends only on the two previous values (`dp[i-1]` and `dp[i-2]`), we can optimize this to **O(1) space** by keeping only two variables:
```python
prev2, prev1 = 1, 2
for i in range(3, n + 1):
    curr = prev1 + prev2
    prev2, prev1 = prev1, curr
return prev1
```

**When to use O(n) vs O(1)?** Use O(n) for clarity and when you need to access intermediate results. Use O(1) when space is critical (embedded systems, large datasets). For interviews, mentioning the O(1) optimization shows deeper understanding.
